# HigherWeb 2.0.1 上手测试

在项目目录运行 `node server.mjs`，打开 http://127.0.0.1:3211/ 。若旧服务正在运行，先在旧终端按 Ctrl+C，再启动。浏览器按 Ctrl+F5 刷新，标题应显示 HigherWeb 2.0.1。

扫码后建议按以下顺序测试：

| 操作 | 预期结果 |
| --- | --- |
| 选择包含免费和已购歌曲的歌单 | 只有权益证据明确且有完整音源的歌曲进入画廊；已购但无音源仍保留购买说明。 |
| 查看“暂不可播放” | 会员覆盖不明确、权益接口失败、仅试听和无音源分别显示原因，不直接断言没有购买。 |
| 全部检查完成后点“重新检查” | 重新发起检查，并刷新账号权益；停止后点“继续检查”只处理尚未完成部分。 |
| 开启历史同步，选一首近期未听的歌正常播放约20秒后切歌 | 原歌曲的已达标记录仍会提交。稍后在酷狗手机端刷新最近播放，核对是否出现；平台可能延迟显示。 |
| 换一首，播放几秒即切歌，或在15秒前拖动到一分钟 | 本轮不提交；跳过的进度不作为实际收听。 |
| 正常暂停再继续，累计实际播放超过15秒 | 暂停时间不计，累计满足后最多提交一次。 |
| 关闭同步再播放；刷新网页 | 保持关闭，不提交；重新开启从零累计当前轮次的真实收听时间。 |
| 单曲循环，或快速切换多首 | 每轮听够后最多提交一次，后端按账号限流；不把检查歌单当作听歌。 |

本版采用保守权益策略：`status=1`、会员有效、可获取完整音源，均不能单独证明某个付费版本属于当前账号。没有明确购买或免费证据的会员歌曲会显示“覆盖范围待确认”；这是待联调的范围，不能据此判断你没有会员或没有购买。

历史同步仅提交“最近听过”，不主动累加播放次数、时长或等级。前端计时防止正常使用时误报，不能作为不可伪造的收听证明。提交失败不会弹窗或自动重试；控制台仅给出脱敏警告。接口接受和手机端实际显示需要分别核对，无法承诺平台账号风控结果。

自动换源会保留原轮次和累计时间，恢复进度不视为用户拖动；本轮已经提交过的记录不会再提交。此项已用离线回归测试覆盖，不建议人为频繁断网来测试真实账号。
