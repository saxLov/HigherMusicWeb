# HigherWeb 2.0.1

酷狗歌单画廊与沉浸播放器，使用原生 HTML/CSS/JavaScript 和本地 Node 服务。

## 运行与测试

需要 Node.js 20+。首次下载本仓库后，先在项目目录运行 `scripts\setup.cmd`，安装固定版本的酷狗连接组件；安装完成后启动：

```powershell
node server.mjs
```

访问 http://127.0.0.1:3211/ ，保持终端开启。更新后先关闭旧服务，再启动并用 Ctrl+F5 刷新；页面标题应显示 HigherWeb 2.0.1。安装脚本只安装运行依赖并禁用依赖安装脚本。仓库不附带 `.runtime/`、账号凭据、运行日志或本机备份。

运行 `npm test` 验证。上手测试步骤见 [测试说明](docs/TESTING-2.0.1.md)，自动测试与离线检查记录见 [验证记录](docs/verification/README.md)。

## 本次修复

- 权益和音源状态分别判断，不再因为能获取完整音源就标记账号已授权。`status=1` 和会员有效也不能单独证明付费版本的覆盖范围。
- 只采用版本匹配的单曲/专辑购买证据，或明确的普通音质免费字段。无法确认的会员覆盖范围显示“待确认”，不会写成“未购买”。
- 已经实际听够15秒的历史独立排队，正常切歌不丢弃；关闭开关、账号变化或退出会取消尚未发送的任务。
- 自动换源保留原轮次与已听秒数，恢复进度不算用户拖动；同轮次已经提交过则不重复提交。
- 全部检查完成后“重新检查”真正发起复查，首首刷新账号权益，其余复用新缓存；停止后的“继续检查”只处理尚未完成的部分。
- 关联音源限制在同专辑、同 MixSongID；实际返回版本不符时拒绝播放。历史上报再次核对版本。
- 上游必须明确返回成功状态才能标记已接受；超时、失败和无法确认的结果均不自动重发。

## 现有操作

扫码连接酷狗，选择歌单后逐首检查；可播放歌曲进入九卡片画廊，其余在“暂不可播放”中按权益、音源、试听、未上架和请求失败分类。滚轮、拖动或左右方向键切歌，空格播放/暂停，F切换沉浸模式，I打开歌单内搜索。搜索候选支持方向键和回车选择，远距离跳转保留最多18帧封面快闪。

沉浸模式包含黑胶、唱臂、三行LRC歌词和真实音频频谱；切换视图不重置音频。歌词可按0.1秒调整并保存。将有使用权的图片放进 `public/Image169/`，可为每首歌绑定背景文件名。

历史同步开关默认开启并保存在当前浏览器。仅真实播放超过15秒才触发，每轮最多一次；暂停和缓冲不计，用户拖动后本轮不提交。服务端按账号节流10秒并防止并发和重复请求。错误仅输出脱敏控制台警告，不弹窗。

目前只提交最近听过，不主动累计次数、时长或等级。接口接受和手机端是否实际显示需要分别验证；前端计时无法成为不可伪造的收听证明，也无法承诺平台风控结果。长时间缺失媒体采样时保守跳过该段计时，避免把未知期间算作真实收听。

## 源码与状态约定

| 文件 | 职责 |
| --- | --- |
| `server.mjs` | 本地服务、会话、同源检查与路由；默认127.0.0.1:3211 |
| `lib/access.mjs`、`entitlements.mjs`、`rights.mjs` | 权益证据、普通音质检查、音源完整性；账号缓存120秒，失败10秒 |
| `lib/inspection.mjs`、`history.mjs` | 30秒会话检查缓存、独立历史上报、账号级限流与去重 |
| `public/app.js` | 页面状态、播放调度和事件绑定 |
| `public/listening.js`、`api-client.js` | 收听轮次与取消边界、按优先级串行请求 |
| `public/player-core.js` | 页面与自动测试共用的媒体加载和队列逻辑 |
| `public/lyrics.js`、`backgrounds.js`、`search.js` | 歌词、背景和搜索；通过defer按index.html顺序加载，仍共享页面状态 |
| `public/style.css`、`styles/` | 样式入口，按基础布局、播放器、歌词顺序覆盖 |

`eligible`、`eligibilityState`、`entitlement` 表示账号权益证据；`playbackState` 表示当次完整音源检查，二者必须同时满足才进入画廊。`playbackIdentity` 保存最终选中音源的hash、专辑和MixSongID，用于版本核对。

歌曲内部ID是组合标识，不直接作为酷狗 `mxid`。历史接口接收 `{songId, hash, playbackId}`，从当前会话已登记记录取平台ID与凭据。平台Cookie/token只留在服务端内存；重启后需要重新扫码。节流和去重同样存于内存，重启后清空。

本次未将历史上报添加到 `/api/play`。检查使用独立 `/api/inspect`，历史使用独立 `/api/report_history`；修改的是共享权益检查器，使原播放路由遵循更严格的判定。

历史操作教程及演示截图说明保存在 [旧版教程](docs/legacy-guide.md)。部分历史CSS覆盖继续保留，本版没有重设计画廊与沉浸布局。
